# 제품 범위 — 국내 비영리 모금 시스템 (2026-10-17)

## 목적
국내 비영리 기관이 **캠페인으로 모금**하고, 모금액을 **투명하게 관리**하며, 회계 자료를 **ERP로 API 전송**하고,
후원자는 **연말정산 증빙(기부금영수증)**을 받는다.

## 핵심 흐름과 담당 모듈
| 단계 | 모듈 |
|---|---|
| 캠페인 | 캠페인·랜딩 빌더·응원 메시지·P2P 개인 모금함·외부 모금 채널(해피빈 등) 정산 |
| 모금 | 일시후원(카드·가상계좌), 정기후원(토스 빌링·CMS), 약정·납입·미납·재청구·환불·카드분쟁, 물품기부, 기업후원(매칭·세금계산서), 결연후원 |
| 투명성 | 공개 공시 페이지(/disclosure), 캠페인 모금 현황, 후원자 임팩트 리포트, 결산 보고서, 감사 로그 |
| ERP | 결제 완료·환불·영수증 발급 시 `erp_outbound_webhooks` 큐 → `erp-outbound-process` 크론이 서명 붙여 전송(재시도·dead letter). 수입결의·전표·계정과목·마감·지출결의도 유지(ERP 없는 기관용) |
| 연말정산 | 기부금영수증(연 1장·재발급·진위 확인) + 국세청 간소화 자료(XLSX) |

## 현금영수증을 발행하지 않는 이유
- 기부금은 재화·용역의 대가가 아니어서 현금영수증 대상이 아니다. 연말정산 공제 증빙은 **기부금영수증**이다.
- 가상계좌·계좌이체 결제에서 현금영수증까지 발행되면 같은 기부를 이중 공제받을 수 있다.
- 그래서 결제 요청에 `cashReceipt: { type: '미발행' }`을 넣는다(`src/app/donate/wizard/steps/Step2.tsx`).
- **운영 확인 필요**: 토스 상점관리자의 현금영수증 자동 발행 설정도 꺼 둘 것. 세부 판단은 세무사 확인 권장.

## ERP 전송 이벤트
| 이벤트 | 시점 |
|---|---|
| `payment.paid` | 일시후원 승인(`lib/donations/confirm.ts`), 정기결제 청구 성공(`lib/billing/charge-one.ts`, 이번 실행이 실제로 완료 처리한 경우만) |
| `payment.refunded` | 환불 완료(`lib/payments/refund.ts`) |
| `receipt.issued` | 기부금영수증 발급(`lib/receipt/issue.ts`) |
- 큐 적재는 예외를 던지지 않는다 — ERP 장애가 결제·환불·발급을 깨지 않는다(기록만 남김).
- ERP 웹훅 주소·서명 키가 없으면 적재하지 않는다(기관 설정 → ERP).

## 이번에 뺀 것 (모금 목적과 무관한 마케팅·CRM 부가 기능)
화면·API·크론에서 제거했다. **DB 테이블은 지우지 않았고** 코드는 git 이력에 남아 되살릴 수 있다.
- 분석: 후원자 라이프사이클, LTV/코호트, 이탈 위험 후원자(점수 재계산·알림 크론 포함), 마케팅 지출 분석
- 마케팅 자동화: 자동화 룰 관리 화면, 설문/NPS, DM 우편 캠페인
- 후원자 참여: 친구 초대(추천 코드) 화면, 배지 부여, 생일 축하, 재활성화 제안, 증액 제안, 라이프사이클 이메일
- 조직 단위(지부) — 단위별 권한이 구현돼 있지 않던 껍데기
- 메뉴의 "CMS EFT 청구" — 화면이 없어 404였음

남긴 것(모금 직결): UTM 분석(유입 채널별 모금), 모금 채널·채널별 통계, P2P 모금, 임팩트 리포트, 감사 편지, 캠페인 마일스톤.
